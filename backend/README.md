# Сервер преподавателя: установка

Сервер нужен, чтобы заявки на допуск, ответы тестов и протоколы студентов приходили **вам**, а вы могли допускать студентов, менять оценки и открывать или закрывать работы в **панели преподавателя**.

Сервер — бесплатный: это Google Таблица на вашем Google-аккаунте и небольшая программа при ней (Google Apps Script). Ничего покупать и устанавливать не нужно. Понадобится только компьютер и ваш Google-аккаунт (тот же, что для Gmail). Установка занимает 15–20 минут и делается один раз.

Пока сервер не подключён, сайт тоже работает — в **локальном режиме**: допуск выдаётся автоматически по баллу, протоколы остаются на устройстве студента, а вам ничего не приходит.

> Названия пунктов ниже — как в русском интерфейсе Google. Если у вас Google на другом языке, порядок действий тот же. Google иногда немного меняет оформление: если кнопка выглядит иначе, ищите её по смыслу.

---

## Шаг 1. Создать таблицу

1. Откройте <https://sheets.google.com> (войдите в свой Google-аккаунт).
2. Нажмите **«Пустая таблица»** (большой «+»).
3. Слева вверху нажмите на «Новая таблица» и назовите её, например, **«Виртуальная лаборатория»**.

В этой таблице будут храниться все заявки и протоколы. **Не давайте никому права на редактирование таблицы** — у редактора будет доступ ко всем данным студентов и к программе.

## Шаг 2. Вставить программу

1. В таблице откройте меню **«Расширения» → «Apps Script»**. Откроется новая вкладка — редактор программы.
2. Слева вверху нажмите на «Проект без названия» и назовите проект **«Виртуальная лаборатория»** → **«Переименовать»**. (Это имя Google покажет на экране разрешений.)
3. Слева в списке «Файлы» уже открыт файл **«Код.gs»**. Справа в нём есть несколько строк (`function myFunction() …`). Выделите всё (**Ctrl + A**, на Mac — **⌘ + A**) и удалите (**Delete**).
4. Откройте файл [`backend/Code.gs`](Code.gs) из этого репозитория (на GitHub — кнопка **«Raw»** или значок «Копировать» над текстом файла), выделите весь текст и скопируйте (**Ctrl + C**).
5. Вернитесь в редактор Apps Script и вставьте (**Ctrl + V**).
6. Нажмите значок дискеты **«Сохранить проект»** (или **Ctrl + S**).

## Шаг 3. Задать логин и пароль

1. Вернитесь на вкладку с таблицей и **обновите страницу** (клавиша **F5** или круглая стрелка в браузере). Через несколько секунд в меню справа от «Справка» появится пункт **«Виртуальная лаборатория»**.
2. Выберите **«Виртуальная лаборатория» → «Задать логин и пароль»**.
3. **В первый раз Google попросит разрешение** — это нормально, программа ваша:
   1. Окно **«Требуется авторизация»** → **«Продолжить»** (или «Проверить разрешения»).
   2. Выберите свой аккаунт.
   3. Появится предупреждение **«Google не проверил это приложение»**. Нажмите внизу слева **«Дополнительные настройки»** (в некоторых версиях — «Дополнительно»), затем **«Перейти на страницу "Виртуальная лаборатория" (небезопасно)»**. Google так пишет про любую программу, которую не проверял сам; эту программу написали для вас, и она работает только с вашей таблицей.
   4. На экране со списком разрешений отметьте **«Выбрать все»** (если есть такая галочка) и нажмите **«Разрешить»** (или «Продолжить»).

   Программа просит доступ к таблице (хранить заявки), к почте (письма о заявках — только если вы их включите), к запуску по расписанию (ежедневная сводка) и к работе в качестве веб-приложения.
4. После разрешения снова выберите **«Виртуальная лаборатория» → «Задать логин и пароль»** (первый запуск мог прерваться из-за окна разрешений).
5. Введите **логин** (латинские буквы и цифры, например `kaldybayeva`) → **ОК**.
6. Введите **пароль** — не короче 8 символов → **ОК**. Повторите пароль → **ОК**.
   Пароль виден на экране, пока вы его вводите, — делайте это без посторонних.
7. Появится сообщение **«Готово…»**. В таблице появятся листы **«Заявки», «Протоколы», «Настройки», «Студенты»**.

Пароль **нигде не хранится в открытом виде**: в «Свойствах скрипта» лежит только его «отпечаток» (хэш с солью), по которому пароль восстановить нельзя. Забыли пароль — просто задайте новый тем же пунктом меню (старые входы в панель при этом перестанут действовать).

## Шаг 4. Опубликовать сервер (веб-приложение)

1. Вернитесь на вкладку **Apps Script**.
2. Справа вверху нажмите синюю кнопку **«Начать развертывание»** (в некоторых версиях — **«Развернуть»**) → **«Новое развертывание»**.
3. Рядом со словами «Выберите тип» нажмите на **шестерёнку** → **«Веб-приложение»**.
4. Заполните:
   - **Описание** — например, «Сервер лаборатории»;
   - **Запуск от имени** — **«Я (ваш адрес)»**;
   - **У кого есть доступ** — **«Все»**.

   «Все» нужно, чтобы студенты могли отправлять заявки без входа в Google. Видеть чужие данные они не могут: каждый студент получает только свои статусы, а заявки и протоколы видны только в панели по вашему логину и паролю.
5. Нажмите **«Начать развертывание»**. Если Google снова попросит разрешение — повторите шаг 3.3.
6. Появится окно **«Новое развертывание»** с полем **«URL веб-приложения»** — длинный адрес, который начинается с `https://script.google.com/macros/s/` и заканчивается на `/exec`. Нажмите **«Копировать»** рядом с ним и нажмите **«Готово»**.
7. Проверка: вставьте этот адрес в новую вкладку браузера. Должна появиться строчка с текстом **«Сервер виртуальной лаборатории работает…»**. Если она есть — сервер работает.

## Шаг 5. Вставить адрес в сайт

Адрес из шага 4 нужно вписать в файл `config.js` в корне сайта.

**На GitHub:**
1. Откройте репозиторий сайта → файл **`config.js`** → значок карандаша **«Edit this file»**.
2. Найдите строку
   ```js
   BACKEND_URL: '',
   ```
   и вставьте адрес **между кавычками**:
   ```js
   BACKEND_URL: 'https://script.google.com/macros/s/ВАШ-АДРЕС/exec',
   ```
   Кавычки и запятая в конце должны остаться.
3. Нажмите **«Commit changes…»** → ещё раз **«Commit changes»**.
4. Через 1–2 минуты GitHub Pages обновит сайт. Студентам, у которых сайт уже был открыт, достаточно обновить страницу.

## Шаг 6. Войти в панель

Откройте адрес сайта и допишите в конце `teacher/`:

```
https://<имя>.github.io/<репозиторий>/teacher/
```

Введите логин и пароль из шага 3 → **«Войти»**. Вход действует 12 часов (или пока вы не нажмёте «Выйти» и не закроете вкладку). После 5 неправильных паролей подряд вход закрывается на 15 минут — это защита от подбора пароля.

В панели:
- **Заявки** — сначала ожидающие решения: ФИО, группа, работа, балл, время; кнопка **«Ответы»** показывает, что студент выбрал в каждом вопросе и какой ответ верный. **«Допустить» / «Не допускать»** с комментарием студенту. Здесь же инструктаж по ТБ и заявки на доступ к сайту.
- **Протоколы** — фильтры по группе, работе, оценке; **«Открыть»** — протокол целиком; можно **изменить оценку** с комментарием и **распечатать / сохранить в PDF**.
- **Студенты** — таблица «студент × работа» с оценками и статусами допуска.
- **Настройки** — доступ к сайту (**всем** / **только одобренным студентам**), по каждой работе: открыта, подсказки, автодопуск; письма на почту.
- **Экспорт CSV** — файл для Excel или Google Таблиц (в каждой вкладке свой).
- Данные обновляются сами раз в 30 секунд.

**Показать на примере** (на странице входа) — панель с вымышленными студентами без сервера, для показа на конкурсе. Можно открыть сразу: `…/teacher/?demo=1`.

### Как решается допуск

- Балл **ниже порога** — сразу «не допущен»: студент может пересдать (новый набор вопросов), не дожидаясь вас. Вы можете изменить решение.
- Балл не ниже порога:
  - **автодопуск выключен** (по умолчанию) — заявка ждёт вашего решения, у студента статус «на рассмотрении»;
  - **автодопуск включён** — допуск выдаётся сразу.
- Инструктаж по ТБ (вводное занятие) работает так же; пока он не одобрен, остальные работы закрыты.

### Письма о заявках

В «Настройках» панели: **«Не присылать»**, **«О каждой новой заявке»** или **«Сводка раз в день»** (около 8:00 по часовому поясу проекта Apps Script: «Настройки проекта» → «Часовой пояс»). Почта — ваша (владельца таблицы) или та, что вы впишете. Gmail отправляет не больше ≈ 100 писем в сутки; если студентов много, выберите сводку. Сводку можно отправить и вручную: меню таблицы **«Виртуальная лаборатория» → «Отправить сводку сейчас»**.

## Если вы изменили код сервера

Когда в репозитории появляется новая версия `backend/Code.gs`:

1. Скопируйте новый текст в редактор Apps Script вместо старого (как в шаге 2) → **«Сохранить проект»**.
2. **«Начать развертывание» → «Управление развертываниями»**.
3. Выберите своё развертывание → значок карандаша **«Изменить»**.
4. В поле **«Версия»** выберите **«Новая версия»** → **«Начать развертывание»** (или «Развернуть»).

Адрес сервера при этом **не меняется** — `config.js` трогать не нужно.
Не выбирайте «Новое развертывание»: у него будет **другой адрес**, и его пришлось бы снова вписывать в `config.js`.

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| Нет меню «Виртуальная лаборатория» | Обновите страницу таблицы и подождите 5–10 секунд. Проверьте, что код сохранён (шаг 2.6). |
| В панели «Логин и пароль ещё не заданы» | Выполните шаг 3. |
| В панели «Сервер ответил не так, как ожидалось» | Адрес в `config.js` неполный или не тот: он должен заканчиваться на `/exec`. Проверьте, что в шаге 4 выбрано «У кого есть доступ: Все». |
| «Нет связи с сервером» | Проверьте интернет. Откройте адрес сервера в браузере (шаг 4.7). |
| Изменили код, а работает по-старому | Обновите развертывание («Новая версия», см. выше). |
| «Слишком много неудачных попыток» | Подождите 15 минут или задайте новый пароль из меню таблицы. |
| Не приходят письма | В «Настройках» панели выбран режим писем? Не исчерпан ли лимит Gmail (меню **«Виртуальная лаборатория» → «Проверить настройку»** показывает остаток)? |
| Студент «пропал» в списке | Студент узнаётся по устройству и ФИО. Если он сменил телефон, браузер или исправил ФИО, его новые записи будут отдельной строкой. |

Студентам: если связи нет, протокол не теряется — он сохраняется на устройстве и отправится сам, как только появится интернет.

## Что где хранится

| Лист | Что в нём |
|---|---|
| **Заявки** | допуски, инструктаж, заявки на доступ к сайту: ФИО, группа, балл, ответы (JSON), решение, комментарий |
| **Протоколы** | протоколы: оценка автоматическая и ваша, штрафные баллы, протокол целиком (JSON) |
| **Настройки** | доступ к сайту, письма, настройки работ — меняйте их в панели, а не вручную |
| **Студенты** | сводка: кто и когда заходил |

Листы можно сортировать и фильтровать, менять ширину и порядок столбцов. **Не переименовывайте листы и заголовки столбцов** — программа находит данные по ним. Строки в «Заявках» и «Протоколах» можно удалять (например, в конце семестра), но лучше сначала сделать копию таблицы: **«Файл» → «Создать копию»**.

Логин, хэш пароля и секрет для входа лежат в **«Свойствах скрипта»** (Apps Script → шестерёнка «Настройки проекта» → внизу «Свойства скрипта»). Не показывайте и не удаляйте их; если удалили — задайте логин и пароль заново из меню.

## Для разработчика

- Протокол: `POST` на адрес `/exec`, тело — `JSON.stringify({action, …})`, `Content-Type: text/plain` (без CORS preflight). Ответ — JSON `{ok: true, …}` или `{ok: false, error, message}`.
- Студент: `submitAdmission {clientId, payload}`, `getStatus {lab, student}`, `submitReport {clientId, payload}`, `getSettings`, `getAccess {student}`, `requestAccess {clientId, student}`. Повтор с тем же `clientId` не создаёт дубль.
- Преподаватель (`token` из `login {login, password}`): `listRequests {kind?, status?}`, `decide {id, status, comment}`, `listReports {lab?, group?}`, `getReport {id}`, `setGrade {id, grade|null, comment}`, `getSettings`, `setSettings {access?, notifyMode?, notifyEmail?, labs?}`, `listStudents`.
- Токен — HMAC-SHA256 с секретом `TOKEN_SECRET` из Script Properties, срок 12 ч. Пароль — HMAC-SHA256 с солью, 500 повторов. Блокировка после 5 неудач — 15 мин (CacheService). Запись — под `LockService`.
- Строки от студентов, начинающиеся с `= + - @`, записываются как текст (без формул). Протокол в ячейке ≤ 50 000 символов — при превышении сокращается журнал.
- Проверка в Node без Google: `node --test tests/api-backend.test.js` (макет Google-сервисов — `tests/api-gas-mock.js`).
