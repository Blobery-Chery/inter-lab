# Техническое задание: Виртуальная лаборатория

> Для сессий Claude, которые строят проект. Сначала прочитай `CLAUDE.md`, затем этот файл, затем `docs/labs.md`.

---

## 1. Цель

Сайт, на котором студент 3 курса выполняет **все лабораторные работы дисциплины «Химия функциональных производных органических молекул»** виртуально, максимально близко к реальной лаборатории:

- **Вводное занятие по технике безопасности и оборудованию** — обязательно, без него все работы закрыты.
- **Допуск к каждой работе** — тест по теории; решение о допуске принимает **преподаватель** (или автоматически, если он так настроил).
- **Сама работа** — реальный ход работы по методичке, шаг за шагом, с реальными количествами, приборами и временем.
- **Ошибки имеют последствия** — от потери выхода до сорванного опыта, как в жизни.
- **Подсказки**, если трудно (их можно выключить для зачёта).
- **Протокол и оценка** — протокол по требованиям методички, автоматическая оценка по 5-балльной шкале.
- **Ответы студентов приходят преподавателю**: заявки на допуск, ответы тестов, протоколы, оценки. Преподаватель входит в **панель по логину и паролю** (вход только для неё), даёт или не даёт допуск, меняет оценку, открывает и закрывает работы.
- **Три языка**: русский, казахский, английский. Переключатель на любой странице.
- Работает на **компьютере и телефоне**; опыты можно выполнять **без интернета** (отправка уйдёт, когда связь появится).

Сайт пойдёт на конкурс в университете. Важны точность содержания, ощущение настоящей лаборатории и аккуратный интерфейс.

**Эталон реализма** — `reference/lab06-07-m-nitrobenzoic-acid.html` (прототип автора по работе № 6–7): аналитические весы с тарированием и дверцами, капельное прибавление с термометром, лабораторное время «День 1 · 09:00», журнал с наблюдениями, замечания с баллами, оценка, протокол из журнала. Каждая работа должна быть не беднее.
Ещё два прототипа автора (`reference/benzoic-acid-*.html`) показывают другие удачные приёмы: «Что будет, если так сделать?» на каждый неверный вариант, разбор «куда делся продукт» (диаграмма потерь), модель с реальными количествами веществ, растворимостью и pH.

## 2. Путь студента

1. **Главная.** Название дисциплины, «как это работает» (инструктаж → допуск → опыты → протокол), поля «ФИО» и «Группа» (обязательны, иначе преподаватель не поймёт, чей результат), список работ карточками со статусом: *закрыта преподавателем*, *нужен инструктаж*, *нет допуска*, *заявка на рассмотрении*, *допуск получен*, *в процессе (опыт N, шаг K)*, *выполнено — оценка N*, *в разработке*.
2. **Страница работы.** Номер, тема, цель, актуальность (кратко). Блок допуска (статус, балл, комментарий преподавателя, кнопка «Пройти / пересдать»). Опыты работы по порядку, у каждого — «Начать / Продолжить / Выполнить заново». Кнопка «Протокол».
3. **Допуск.** Краткая теория (сворачиваемая) → тест → результат с разбором → «Заявка отправлена преподавателю» → ожидание решения (автопроверка статуса раз в 30 с и кнопка «Проверить»).
4. **Опыт.** Как в эталоне: этапы сверху, слева (на телефоне — сверху) **стенд** — SVG-сцена, справа **панель шага**: инструкция, органы управления, показания приборов, обратная связь, «Подсказка», «Далее». Рядом — **лабораторный журнал** (время, действия, наблюдения, замечания) и сворачиваемая памятка ТБ работы.
5. **Протокол** — по требованиям раздела 8 методички каждой работы: опыты, реактивы с количествами, уравнения, наблюдения, расчёты со своими числами, итоговая таблица, выводы, индивидуальное задание, замечания, оценка. Отправляется преподавателю автоматически, печать / PDF.

Маршруты (хэш, чтобы работало на GitHub Pages): `#/` · `#/lab/08` · `#/lab/08/admission` · `#/lab/08/exp/2` · `#/lab/08/report`.

## 5. Типы шагов

Интерфейс типа шага:

```js
export default {
  type: 'weigh',
  init(step, ctx) {},
  render(step, ctx) {},                  // → HTML панели шага
  bind(root, step, ctx) {},
  hints(step, ctx) { return [l1, l2, l3] }
}
// ctx: { state, lang, t, rng, clock.advance(sec), log(text, kind), remark({key, severity, points, text, effect}),
//        solve(feedback), scene.update(), instruments }
```

Базовый набор (сессия движка делает все; работа может добавить свой тип в своей папке):

| Тип | Что делает студент | Проверка и последствия |
|---|---|---|
| `checklist` | Надевает СИЗ, включает тягу, находит средства аварийной защиты (как первый шаг эталона) | Всё нужно отметить; неверный пункт (если есть) — замечание |
| `pick` | Выбирает посуду, приборы, реактивы с полки с лишними предметами | Лишнее / недостающее → замечание; динамические подсказки |
| `assemble` | Собирает установку на стенде (нажать предмет → нажать место) | Неправильная сборка разрешена, но даёт последствие позже (протечка, потери, авария закрытой системы) |
| `weigh` | Навеска на весах: лодочка/стекло, тара, дверцы, порошок шпателем | Без тары, с открытыми дверцами, на голую чашку → замечания; реальная масса уходит в state |
| `measure` | Отмеряет жидкость цилиндром, пипеткой, бюреткой (уровень, мениск) | Цена деления прибора; отклонение → последствие в state (`onDeviation: 'block' \| 'consequence'`) |
| `add` | Прибавляет реагент: сразу / порциями / по каплям, следя за прибором | Скорость влияет на state (перегрев, выброс, побочные продукты) |
| `process` | Управляет параметром во времени: нагрев, охлаждение, перемешивание, выдержка | Зоны *ниже / норма / быстро / перебор*; перебор → потери или авария; **события** по ходу (бурые пары, толчки, вспенивание) с решением |
| `decide` | Выбирает действие из вариантов | У каждого варианта `severity`, `points`, `effect(state)` и текст «Что будет, если так сделать?»; `retry: true/false` |
| `order` | Расставляет операции по порядку | Первая неверная позиция → замечание |
| `separate` | Фильтрование (что оставить: фильтрат/осадок, чем промыть), разделение слоёв в делительной воронке | Выбор не того → продукт уходит в отходы (как в эталоне по бензойной кислоте) |
| `test` | Качественная проба в пробирке: добавить реактив, нагреть, наблюдать | Наблюдение **считается из state**: если раньше была ошибка, картина другая |
| `observe` | Описывает наблюдение (цвет, осадок, газ, запах, зеркало…) | Верный ответ зависит от state |
| `read` | Снимает показание: термометр, шкала, прибор т. пл., поляриметр, индикаторная бумага | Допуск по цене деления |
| `calc` | Считает по своим данным: выход, удельное вращение, оптическая чистота… | Относительная погрешность ≤ 1 %; 3 попытки, затем решение (засчитывается как подсказка) |
| `quiz` | Вопросы внутри опыта (как допуск в эталоне) | Каждая ошибка — замечание с баллом |
| `cleanup` | Утилизация отходов по контейнерам, выключение приборов, мытьё посуды | Неверный контейнер / раковина → замечание |

## 6. Модель последствий (главное требование заказчика)

«Если сделал ошибку — там последствия».

**Состояние.** У каждого опыта есть `state` с реальными количествами (ммоль, г, мл), температурой и её историей, временем, чистотой, флагами (*посуда мокрая*, *продукт влажный*, *перегрев был*, *избыток реагента*…). Сцена, показания приборов, наблюдения и результаты считаются из него. Где методичка даёт данные (молярные массы, т. пл., pKa, растворимость), модель опирается на них.

**Тяжесть ошибки:**

| Уровень | Что происходит | Баллы (по умолчанию) |
|---|---|---|
| `minor` | Нарушение порядка без влияния на результат; замечание с объяснением | 0,5 |
| `major` | Влияет на результат: потеря продукта, примеси, систематическая погрешность. Опыт продолжается, итог хуже, в протоколе видно почему | 1 |
| `critical` | Опасно или необратимо. Экран «Что произошло бы в реальной лаборатории» (спокойно, без натурализма), опыт сорван, перезапуск с контрольной точки; в протоколе — как аварийная ситуация | 2 |
| `safety` | Нарушение ТБ без немедленной аварии (без очков, вне вытяжного шкафа, кислота в раковину) | 1 |

**Отложенные последствия.** Ошибка не обязана проявиться сразу: выход упадёт, т. пл. будет заниженной и растянутой, проба даст другую окраску. Протокол связывает причину и следствие.

**Разбор «куда делся продукт».** Для синтезов в протоколе — диаграмма потерь по этапам (как в эталоне по бензойной кислоте).

**Реалистичный разброс.** Генератор по seed (seed — номер попытки): у каждой попытки свои цифры, приборы шумят в пределах своей точности. Если всё сделано верно, результат попадает в диапазон методички (выход, т. пл., вращение).

**Основание.** Последствия следуют из методички и реальной лабораторной практики. Всё, чего нет в методичке явно, — запись в `labs/lab-NN/ASSUMPTIONS.md`.

**Минимум на каждую экспериментальную работу:** ≥ 3 ошибки уровня `major`, ≥ 1 сценарий `critical`, ≥ 2 замечания `safety`, ≥ 1 отложенное последствие, ≥ 1 событие внутри процесса. Для работ из одних качественных проб (10, 11, 15) — ошибки, меняющие наблюдение (не та последовательность реактивов, не та температура бани, грязная пробирка), и не меньше одного `critical`.

## 7. Подсказки

- Кнопка «Подсказка» на каждом шаге, **три уровня**: (1) направление — где смотреть, о чём подумать; (2) конкретика — исключить неверный вариант, назвать порядок величины; (3) решение с объяснением.
- Движок даёт подсказки по умолчанию для каждого типа шага; работа может переопределить текст.
- Подсказки пишутся в журнал и в протокол. Уровни 2 и 3 стоят 0,25 и 0,5 балла.
- Подсказки выключаются: ссылкой `?mode=exam` или преподавателем в настройках работы (раздел 19). Протокол помечается «контрольный режим».

## 8. Допуск

- Банк вопросов на работу — **не меньше 15**, из раздела 4 методички (вопросы для самоконтроля), теории (раздел 3), хода работы и ТБ. В тесте случайные `pick` (по умолчанию 5), порог `pass` (по умолчанию 4).
- Варианты перемешиваются; после проверки — верно/неверно и объяснение к каждому вопросу.
- Результат с ответами отправляется преподавателю как **заявка на допуск** (раздел 19). Пока решения нет — опыты закрыты, статус «на рассмотрении». Если преподаватель включил автодопуск — решение сразу по порогу.
- Отказ показывается с комментарием преподавателя; пересдача — новый случайный набор.
- Без настроенного сервера (`BACKEND_URL` пуст) допуск выдаётся автоматически по порогу — сайт полностью работает и так.

## 9. Журнал и лабораторное время

Как в эталоне: часы «День 1 · 09:00», каждое действие сдвигает время на реальную длительность (выдержка 15 мин, сушка 24 ч → «День 2»). Записи: действие, наблюдение («Набл.»), замечание (красным). Журнал переносится в протокол.

## 10. Протокол и оценка

- **Структура — раздел 8 методички каждой работы**: для каждого опыта название и реактивы с количествами, уравнения, наблюдения (точные, не «положительно/отрицательно»), расчёты со своими числами, вывод; итоговая таблица из методички; индивидуальное задание; замечания с баллами; число подсказок; оценка.
- **Оценка** (как в эталоне): сумма баллов замечаний и подсказок → 5 (≤ 1), 4 (≤ 3), 3 (≤ 5,5), 2 (> 5,5). Пороги — в `app/grading.js`. Плюс баллы за плохой результат, если методичка задаёт норму (например, выход ниже порога, т. пл. ниже литературной).
- **Индивидуальное задание** (раздел 8 методички): задачи с автопроверкой (расчёт, выбор продукта, порядок стадий механизма) и одно поле свободного ответа, который читает преподаватель.
- ФИО и группа подставляются из профиля, их можно поправить.
- Протокол **отправляется преподавателю автоматически** (раздел 19); на экране — «Отправлено ✓» или «В очереди — отправится при подключении».
- Печать: A4, чёрное на белом (`@media print`). «Скачать PDF» = печать в PDF средствами браузера.

## 11. Хранение

`localStorage`, префикс `vlab_`, поле `schemaVersion`, все обращения в `try/catch`. Сохраняется: язык, ФИО, группа, deviceId, статусы допусков, незавершённые опыты (с текущего шага), протоколы, очередь неотправленного (outbox). «Сбросить прогресс» — с подтверждением.

## 18. Вводное занятие `lab-00`: техника безопасности и оборудование

Обязательно для всех; без него работы 6–15 закрыты (п. 1.3 правил ТБ: «не прошедший инструктаж… не допускается»). Источник — `docs/source/safety-rules-ru.md` (разделы 1–14) и оборудование всех работ (`docs/labs.md`).

Этапы:
1. **Лаборатория глазами инспектора** — сцена лаборатории, найти нарушения раздела 2 (еда, распущенные волосы, сумки на столе, набор пипеткой ртом, работа в одиночку при нагреве…).
2. **СИЗ** — одеться для работы (раздел 3): хлопковый халат, очки (контактные линзы — нет), перчатки по реактиву (нитрил / бутилкаучук), закрытая обувь.
3. **Реактивы, ЛВЖ, кислоты и щёлочи** (разделы 4–6) — ситуации с последствиями: вода в кислоту (critical), эфир на открытом пламени (critical), эфир в раковину, возврат реактива в склянку, нейтрализация пролива (NaHCO₃ / разб. уксусная кислота).
4. **Нагрев, перегонка, электричество, стекло** (разделы 7–9) — нагрев закрытой системы (critical), кипелки, шлифы, термометр в пробку, мокрые руки и плитка, бой стекла.
5. **Отходы** (раздел 10) — рассортировать по четырём контейнерам.
6. **Пожар и первая помощь** (разделы 11–13) — горит стакан (часовое стекло / влажная ткань; вода — critical), загорелась одежда, попадание в глаза, ожог, вдыхание паров, проглатывание.
7. **Оборудование** — каталог всей посуды и приборов работ 6–15 (узнать, назначение), сборка типовых установок: обратный холодильник, простая перегонка, вакуумное фильтрование, делительная воронка, прибор т. пл., поляриметр, ледяно-солевая баня. Ошибки сборки с последствиями (вода в холодильник сверху, закрытая система, нет кипелок).
8. **Итоговый тест** — банк ≥ 30 вопросов, 10 случайных, порог 8.
9. **Запись в журнале инструктажа** — дата, ФИО, группа, «С правилами ознакомлен(а)»; уходит преподавателю как заявка (тип `briefing`). После одобрения открываются работы.

## 19. Преподаватель: сервер, панель, отправка результатов

### Сервер — Google Apps Script + Google Таблица преподавателя

Бесплатно, без сторонних аккаунтов: всё хранится в Google Таблице на Google-аккаунте преподавателя. Код — в `backend/Code.gs`, инструкция по установке для человека без опыта программирования — в `backend/README.md` (по шагам, с точными названиями пунктов меню Google).

- Скрипт **привязан к таблице** (Расширения → Apps Script). Листы: `Заявки` (допуски и инструктаж), `Протоколы`, `Настройки` (по работам: открыта, подсказки, автодопуск; почта для уведомлений), `Студенты` (сводка).
- **Логин и пароль преподавателя** задаются из меню таблицы «Виртуальная лаборатория → Задать логин и пароль» (`SpreadsheetApp.getUi().prompt`), хранятся в Script Properties как хэш с солью. В репозитории пароля нет никогда.
- Вход: `login` → токен (HMAC-SHA256 с секретом из Script Properties, срок 12 ч). После 5 неудачных попыток — блокировка на 15 минут (CacheService).
- Публикация: Развернуть → Веб-приложение, «Выполнять от имени: я», «Доступ: все». URL вставляется в `config.js` (`BACKEND_URL`).
- Запросы из браузера: `fetch(BACKEND_URL, {method:'POST', body: JSON.stringify({action, …})})` с типом `text/plain` (без preflight), ответ — JSON через `ContentService`. Запись — под `LockService`.
- Действия студента: `submitAdmission`, `getStatus`, `submitReport`, `getSettings`. Студент видит только свои записи (по `deviceId` + ФИО).
- Действия преподавателя (с токеном): `login`, `listRequests`, `decide` (одобрить/отклонить + комментарий), `listReports`, `getReport`, `setGrade`, `getSettings`, `setSettings`, `listStudents`.
- Уведомление на почту о новой заявке на допуск — по настройке (учесть лимит Gmail ≈ 100 писем в сутки; есть вариант «сводка раз в день» по триггеру).
- Длинные протоколы: в ячейку — JSON (лимит ячейки 50 000 символов; при превышении журнал сокращается).

### Панель преподавателя `teacher/index.html`

- Вход по логину и паролю; токен в `sessionStorage`; «Выйти».
- **Заявки**: сначала ожидающие; ФИО, группа, работа, балл, время; раскрыть ответы (какой вопрос, что выбрал, верный ответ); «Допустить» / «Не допускать» + комментарий. Тот же список для инструктажа `lab-00`.
- **Протоколы**: список с фильтрами (группа, работа, оценка); открыть протокол целиком как у студента; изменить оценку с комментарием.
- **Студенты**: таблица «студент × работа» со статусами и оценками по группе.
- **Настройки работ**: открыта / закрыта, подсказки вкл / выкл, автодопуск вкл / выкл.
- Экспорт в CSV. Автообновление раз в 30 с. Три языка, телефон и компьютер, тот же дизайн.

### Контракт `app/api.js` — ЗАФИКСИРОВАН

Файл уже лежит в репозитории с локальной реализацией. Движок и работы вызывают **только эти функции** и не меняют файл. Сессия «Преподаватель» реализует сетевой режим внутри того же файла, сохраняя сигнатуры.

```js
api.isConnected()                     // true, если в config.js задан BACKEND_URL
api.getStudent() / api.setStudent({name, group})   // + deviceId создаётся автоматически
api.submitAdmission(payload)          // → {ok, id, status}   status: 'pending'|'approved'|'denied'
api.getStatus(labId)                  // → {status, score, comment, decidedAt} | null
api.submitReport(payload)             // → {ok, id, queued, local}   local: сервер не настроен, сохранено на устройстве
api.getSettings()                     // → {labs: {[labId]: {open, hints, autoAdmit}}}
api.flushOutbox()                     // отправить очередь (вызывать при старте и по событию online)
```

Формат `payload` — в комментариях `app/api.js`.
